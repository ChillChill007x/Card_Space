# Cardspace — ตลาดซื้อขายการ์ดสะสม

เว็บแอปพลิเคชันซื้อขายการ์ดสะสม (Pokémon, Yu-Gi-Oh!, One Piece, Magic: The Gathering) ทีละใบ ระหว่างผู้ซื้อกับร้านค้าที่ผ่านการยืนยันตัวตน ใช้ **เครดิตสาธิต** แทนเงินจริง

รายวิชา CP363205 ภาษาอนุกรมข้อมูลและการประยุกต์

- Back-end: **Node.js + Express 5** (REST API)
- ฐานข้อมูล: **MongoDB** ผ่าน Mongoose (ดูข้อมูลด้วย MongoDB Compass หรือใช้ Atlas ได้)
- Front-end: HTML, CSS, JavaScript (ES Modules) เรียก API ด้วย `fetch`
- เพิ่มเติม: OCR อ่านการ์ดจากรูปด้วย tesseract.js และย่อ/ตรวจรูปด้วย sharp

โครงสร้างข้อมูล (JSON Map) และรายการ API ทั้งหมด (API Map) อยู่ที่ [docs/architecture.md](docs/architecture.md)

## ติดตั้งและรัน

### สิ่งที่ต้องมี

- Node.js **22.9 ขึ้นไป**
- MongoDB ในเครื่อง (`mongodb://127.0.0.1:27017`) หรือ MongoDB Atlas

### ขั้นตอน

1. ติดตั้งแพ็กเกจ

   ```bash
   npm install
   ```

2. สร้างไฟล์ `.env` จากแม่แบบ แล้วแก้ค่าให้ตรงกับเครื่อง

   ```bash
   cp .env.example .env
   ```

   | ค่า | จำเป็น | ความหมาย |
   |---|---|---|
   | `MONGODB_URI` | ✅ | เช่น `mongodb://127.0.0.1:27017/cardspace` หรือ connection string ของ Atlas |
   | `ADMIN_EMAIL`, `ADMIN_PASSWORD` | แนะนำ | สร้างบัญชีแอดมินตอนเริ่มเซิร์ฟเวอร์ (รหัสผ่านอย่างน้อย 12 ตัวอักษร สร้างเฉพาะเมื่ออีเมลนี้ยังไม่มี) |
   | `PORT` | – | ค่าเริ่มต้น `3000` |
   | `CONTACT_EMAIL` | – | อีเมลที่แสดงในหน้า "ติดต่อ" |
   | `AUTO_COMPLETE_DAYS` | – | จำนวนวันหลังจัดส่งก่อนยืนยันรับอัตโนมัติ (ค่าเริ่มต้น 7) |

3. เริ่มเซิร์ฟเวอร์ แล้วเปิด http://localhost:3000

   ```bash
   npm start
   ```

### คำสั่งทั้งหมด

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `npm start` | รันด้วย MongoDB (ถ้าไม่มี `MONGODB_URI` เซิร์ฟเวอร์จะไม่เริ่มและแจ้งเหตุผล) |
| `npm run dev` | เหมือน `start` แต่รีสตาร์ตเองเมื่อแก้โค้ด |
| `npm run demo` | โหมดสาธิตในหน่วยความจำ มีการ์ดตัวอย่าง 8 ใบ ข้อมูลหายเมื่อปิดเซิร์ฟเวอร์ |
| `npm run seed:demo` | เพิ่มการ์ดตัวอย่างลง MongoDB (รันซ้ำได้ ไม่สร้างซ้ำ) |
| `npm test` | ชุดทดสอบอัตโนมัติ |
| `node scripts/mongodb-check.js` | ทดสอบกับ MongoDB จริงบนฐานทดสอบแยก แล้วลบทิ้งเอง |

> ถ้าไดรฟ์ C เต็ม: `.npmrc` ตั้ง npm cache ไว้ใน `.local-runtime/` แล้ว และรัน `. .\scripts\use-e-drive.ps1` ใน PowerShell ก่อนเพื่อย้ายไฟล์ชั่วคราวมาไดรฟ์ E

### ลองใช้งานเร็ว ๆ

1. สมัครบัญชี **พ่อค้า** → กรอกข้อมูลยืนยันร้านพร้อมแนบรูป
2. เข้าสู่ระบบด้วยบัญชี **แอดมิน** (จาก `.env`) → กระดิ่งแจ้งเตือน → อนุมัติร้าน
3. กลับเป็นพ่อค้า → "ลงขายการ์ด" อัปโหลดรูปแล้วกด "อ่านข้อมูลจากรูปด้านหน้า"
4. สมัครบัญชี **ผู้ซื้อ** → เติมเครดิต → ค้นหาการ์ด → ซื้อ
5. พ่อค้าแจ้งจัดส่ง → ผู้ซื้อยืนยันรับหรือแจ้งปัญหา → ให้คะแนนร้าน

## ความปลอดภัยและความถูกต้องของข้อมูล

- รหัสผ่าน hash ด้วย scrypt ส่วน session เก็บเป็น hash ฝั่งเซิร์ฟเวอร์ และส่งให้เบราว์เซอร์เป็น cookie แบบ HttpOnly + SameSite
- API ตรวจสิทธิ์ตามบทบาททุกครั้ง โดยไม่เชื่อค่าจากหน้าเว็บ เช่น ราคา เจ้าของ หรือสถานะ
- **กันขายซ้ำและแก้ข้อมูลหลังขาย**: การซื้อ แก้ไข และลบการ์ดตรวจ "ยังไม่ขาย" ในคำสั่งเดียวกับการเขียนข้อมูล
- **กันหักเงินซ้ำ**: คำขอเกี่ยวกับเงินต้องมี `Idempotency-Key` ส่งซ้ำแล้วได้ผลเดิม และการหักเครดิตตรวจยอดคงเหลือในคำสั่งเดียวกัน
- รูปตรวจชนิดไฟล์จากข้อมูลจริง (ไม่ใช่แค่นามสกุล) และจำกัดขนาด 2 MB ส่วนหลักฐานส่วนตัวดูได้เฉพาะคู่ค้าและแอดมิน
- ราคาและเครดิตเก็บเป็นจำนวนเต็มหน่วยสตางค์

## ข้อจำกัด

- เป็นระบบต้นแบบ **ยังไม่รับเงินจริงและไม่มีการจัดส่งจริง** โหมด `NODE_ENV=production` จะปิดการเติมเครดิตและการซื้อ
- MongoDB แบบ standalone ไม่มี transaction ข้ามหลายเอกสาร ระบบจึงย้อนขั้นก่อนหน้าให้เองเมื่อขั้นถัดไปล้มเหลว แต่ถ้าเซิร์ฟเวอร์ดับกลางขั้นตอนอาจต้องแก้ข้อมูลด้วยมือ ก่อนใช้เงินจริงควรใช้ replica set หรือ Atlas พร้อม transaction
- ยังไม่มีระบบลืมรหัสผ่าน และการจำกัดความถี่การเข้าสู่ระบบเก็บในหน่วยความจำ
- OCR เป็นเพียงข้อเสนอ ผู้ขายต้องตรวจข้อมูลเอง และเว็บไซต์ยังไม่ได้ยืนยันเลขใบรับรองเกรดกับบริษัทให้เกรด
- การ์ดตัวอย่างและภาพ SVG เป็นข้อมูลสมมติ ไม่ใช่ภาพการ์ดลิขสิทธิ์จริง
